## F) Interview Plan

### STAR+R Stories (7 stories mapped to JD requirements)

**Story 1: Multi-Agent ERP Assistant**
- **JD Requirement:** Build agents end-to-end
- **Situation:** Company needed an autonomous document-driven query system for ERP finance intelligence.
- **Task:** Architect and deploy a multi-agent assistant that could handle document uploads, query finance data, and provide insights.
- **Action:** Designed agent flow using custom orchestration, integrated retrieval, prompt chaining, and fallback mechanisms. Deployed on GCP with Redis caching.
- **Result:** Production-ready system handling 1,000+ requests/hour, with 99.5% uptime.
- **Reflection:** Learned that agent state management is critical — retry logic and idempotency saved us during peak loads.

**Story 2: Inference Optimization (Llama 3 70B)**
- **JD Requirement:** Cost and latency engineering for LLM workloads
- **Situation:** Fine-tuning Llama 3 70B was too slow for production timelines.
- **Task:** Improve inference throughput and reduce latency.
- **Action:** Applied TensorRT-LLM, vLLM, INT8/FP8 quantization, and KV-cache optimization. Implemented distributed GPU infrastructure with Redis caching.
- **Result:** 40% throughput increase, 35% latency reduction.
- **Reflection:** Quantization requires careful eval — we built a regression test suite to catch quality drops.

**Story 3: RAG Pipeline for Geospatial Platform**
- **JD Requirement:** RAG patterns (chunking, embeddings, hybrid search, reranking)
- **Situation:** Urban transport planning platform needed to retrieve relevant documents from a large corpus.
- **Task:** Build a scalable RAG pipeline with high accuracy.
- **Action:** Used Postgres + pgvector for embeddings, implemented chunking strategies, hybrid search (BM25 + dense), and reranking.
- **Result:** 12k+ documents indexed with <200ms retrieval latency.
- **Reflection:** Chunk size and overlap were the most impactful hyperparameters — we A/B tested before production.

**Story 4: Distributed GPU Infrastructure with Redis**
- **JD Requirement:** Observability, caching, reliability
- **Situation:** Multi-node inference was hitting latency spikes due to cache misses.
- **Task:** Design a caching layer and health check system.
- **Action:** Implemented Redis caching with TTL strategies, built health checks, fallback to single-node, and set up W&B dashboards for latency and drift.
- **Result:** 35% latency reduction, proactive incident detection.
- **Reflection:** Observability is not just metrics — structured logging saved us during debugging a memory leak.

**Story 5: Document Intelligence System (GCP/Azure, Gemini 1.5)**
- **JD Requirement:** Integration with third-party APIs, multilingual processing
- **Situation:** Needed to process 1,000+ high-resolution document requests/hour in multiple Indian languages.
- **Task:** Build a scalable system using Gemini 1.5 for translation and extraction.
- **Action:** Designed pipeline on GCP with Azure for redundancy, used Gemini API for structured output, set up W&B for monitoring.
- **Result:** System processed 1M+ requests with 98% accuracy.
- **Reflection:** API rate limits were a challenge — we implemented exponential backoff and queue management.

**Story 6: Tamil Vision-OCR Pipeline**
- **JD Requirement:** Structured extraction, LLM-powered translation, regulated domain
- **Situation:** Needed OCR and translation for Tamil documents in a high-accuracy, auditability-critical domain.
- **Task:** Build a pipeline that extracts structured data, translates to English, and stores audit trails.
- **Action:** Combined OCR, LLM-based correction, and translation. Designed for 100% auditability.
- **Result:** High accuracy with full audit trail.
- **Reflection:** Regulated domains require explainability — we added confidence scores and human review checkpoints.

**Story 7: Open Source Contributions (vLLM & LLMCache)**
- **JD Requirement:** Bonus: open-source contributions in agent/LLM ecosystem
- **Situation:** Noticed gaps in vLLM documentation for KV-cache and LLMCache for cache reuse.
- **Task:** Contribute to improve usability.
- **Action:** Authored documentation for KV-cache optimization, proposed cache reuse strategies for repeated prompt workloads.
- **Result:** Both contributions merged and used by the community.
- **Reflection:** Open source taught me system design at scale — understanding how inference engines work helped me debug production issues faster.
